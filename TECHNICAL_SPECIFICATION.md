# Техническое задание
## Информационная система «SPKBOT MAX»

---

## 1. Общие сведения

### 1.1. Наименование проекта
**SPKBOT MAX** — многофункциональная информационная система для студентов и сотрудников Северского промышленного колледжа.

### 1.2. Область применения
Система предназначена для:
- Просмотра актуального расписания занятий
- Подачи электронных заявок на справки и услуги
- Получения документов и информации через Telegram-бота
- Автоматизации работы администрации по обработке заявок

### 1.3. Краткая характеристика
Система представляет собой веб-приложение с Telegram-ботом и административной панелью. Архитектура включает:
- **Frontend**: React-приложение (мини-приложение для Telegram WebApp)
- **Backend**: FastAPI REST API
- **Telegram Bot**: асинхронный бот на aiomax
- **Database**: PostgreSQL
- **Admin Panel**: sqladmin для управления данными

---

## 2. Функциональные требования

### 2.1. Модуль «Расписание»

#### 2.1.1. Назначение
Предоставление студентам доступа к актуальному расписанию занятий.

#### 2.1.2. Функциональные возможности
- Просмотр списка учебных групп
- Выбор группы для отображения расписания
- Переключение между типами недель (чётная/нечётная)
- Просмотр расписания на:
  - Сегодня
  - Завтра
  - Произвольный день недели
- Отображение информации о занятиях:
  - Номер пары
  - Название предмета
  - Кабинет
  - Преподаватель
  - Время начала и окончания
  - Подгруппа (при разделении)

#### 2.1.3. Источник данных
Расписание загружается из Excel-файла (`rasp.xlsx`), размещённого на фронтенде. Парсинг выполняется на стороне backend с помощью библиотеки `pandas`.

#### 2.1.4. API эндпоинты
| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/groups` | Получение списка групп |
| GET | `/api/schedule/{group_name}` | Получение расписания для группы |

---

### 2.2. Модуль «Заявки»

#### 2.2.1. Назначение
Электронная подача заявок на получение справок и услуг колледжа.

#### 2.2.2. Функциональные возможности
- Просмотр доступных услуг (кнопок)
- Заполнение динамических форм с вопросами
- Поддержка типов полей:
  - Текст (одна строка)
  - Многострочный текст
  - Email
  - Телефон
  - Число
  - Выпадающий список
  - Дата
- Валидация обязательных полей
- Отправка заявки
- Просмотр истории собственных заявок
- Отслеживание статуса заявки:
  - 🔵 Новая
  - 🟡 В обработке
  - 🟢 Готова
  - ✅ Выдана
  - 🔴 Отклонена
  - ⚫ Отменена

#### 2.2.3. API эндпоинты
| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/buttons` | Список доступных услуг |
| GET | `/api/buttons/{id}/form` | Форма для услуги |
| POST | `/api/submissions` | Создание заявки |
| GET | `/api/submissions/my` | История заявок пользователя |

---

### 2.3. Модуль «Профиль»

#### 2.2.1. Назначение
Управление персональными данными пользователя.

#### 2.2.2. Функциональные возможности
- Отображение данных из Telegram (ID, имя)
- Редактирование ФИО
- Привязка учебной группы
- Сохранение данных в localStorage

---

### 2.4. Telegram-бот

#### 2.4.1. Назначение
Предоставление доступа к информации и документам колледжа через мессенджер Telegram.

#### 2.4.2. Функциональные возможности
- Команда `/start` — приветствие и главное меню
- Навигация по разделам сайта колледжа:
  - 📚 Сведения об образовательной организации
  - 🎯 Профессионалитет
  - 🎓 Целевое обучение
  - 👨‍🎓 Студенту
  - 👩‍🏫 Сотруднику
  - ⚡ Центр IT
  - 💬 Обратная связь
- Парсинг документов с веб-страниц колледжа
- Отправка файлов пользователю
- Поддержка пагинации при большом количестве файлов
- Кнопки возврата к предыдущим меню

#### 2.4.3. Структура разделов
Каждый раздел содержит категории, соответствующие страницам сайта `spospk.ru`.

---

### 2.5. Административная панель

#### 2.5.1. Назначение
Управление данными системы уполномоченными сотрудниками.

#### 2.5.2. Функциональные возможности
- **Аутентификация**: вход по логину и паролю с проверкой роли «Админ»
- **Управление пользователями**:
  - Просмотр списка пользователей
  - Поиск по ФИО, логину, max_id
  - Добавление/редактирование
- **Управление кнопками (услугами)**:
  - Создание/редактирование кнопок
  - Активация/деактивация
  - Настройка порядка отображения
- **Управление формами**:
  - Привязка формы к кнопке
  - Добавление вопросов из справочника
  - Настройка обязательности полей
- **Управление вопросами**:
  - Справочник переиспользуемых вопросов
  - Настройка типа поля, валидации, вариантов ответа
- **Управление заявками**:
  - Просмотр всех заявок
  - Изменение статуса
  - Добавление комментариев
  - Просмотр ответов пользователей

## 5. Требования к безопасности

### 5.1. Аутентификация и авторизация
- Административная панель: сессионная аутентификация с проверкой роли
- API мини-приложения: заголовок `X-User-Id` (в дальнейшем рекомендуется заменить на JWT)
- Telegram WebApp: использование `initDataUnsafe` для идентификации

### 5.2. Защита данных
- Пароли пользователей хранятся в открытом виде (⚠️ требуется доработка)
- Сессионные данные подписываются `SECRET_KEY`
- CORS настроен для развития (требуется ограничение в production)
